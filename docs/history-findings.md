# 历史巡查图片真值与线路规律

## 数据范围与标注口径

- 数据来自 `data/history/manifest.json`、`data/history/vision-ocr.json`、`detail.md` 及 `01589`、`01591` 至 `01598` 的原图。
- 共 9 条历史记录、66 张图片；所有图片均为正式历史记录附件，因此 `include` 均标为 `true`。
- `expectedName` 仅用于人工核验真值，没有作为图片分类输入。附件名、正文、图像、水印发生冲突时，优先级为：图中唯一性文字/坐标 > 水印时间和路线时序 > 正文 > 附件名。
- `expectedTime` 使用中国标准时间，格式为 `YYYY-MM-DD HH:mm:ss`。图片没有可见时间且正文不能唯一对应时为 `null`。
- `sequenceIndex` 是同一 `recordId` 内按真实时间排列的序号。重复视角可以占相邻序号；无法判断所属上午/下午治超时段时为 `null`。
- `direction` 使用 `toward_pingan`、`toward_xining`、`toward_huangyuan`、`toward_huzhu`、`turnaround`、`stationary`、`connector_east`、`return_city`。
- 低置信度定义为 `confidence < 0.80`。当前有 5 张：`01592/02`、`01592/05`、`01592/11`、`01593/05`、`01598/11`。

## G6 平安至西宁

### 标准主序列

西宁向平安的常见顺序：

1. 同仁路口/柴达木路连接段进入
2. 朝阳互通立交 K1800+500
3. 站西巷匝道 K1797+700
4. 站东巷匝道 K1795+000
5. 民和路出口 K1792+400
6. 韵家口立交 K1790+600
7. 峡口立交/峡口匝道 K1786+200
8. 海东主线收费站 K1779+800
9. 曹家堡 K1774+300
10. 曹家堡东 K1768+800
11. 平安收费站 K1766+600

平安调头返回西宁时顺序反转。历史记录通常只拍朝阳、海东主线、平安三个骨干点，峡口、曹家堡、机场匝道、施工点和治超点按当天任务插入。

### 可选点位与事件

- 柴达木路延伸段、同仁路口、南辅路、S1113宁贵高速：属于进出主线的连接段，不能仅凭这些地名判定为西过境或S101。
- 曹家堡机场匝道：图中可直接出现“曹家堡机场”路牌。
- 曹家堡收费站、曹家堡西收费站：与曹家堡东 K1768+800 不是同一语义点。
- 西宁东收费站：`01592/10`、`01598/10` 顶棚文字可直接识别为“西宁东收费站”。正文在相同时间写作“海东主线收费站”，两者不能在真值中无条件合并。
- K1771-K1774绿化施工：水印可能给出“西宁曹家堡国际机场”或G0611等附近POI，应依靠施工画面、时间和正文确定。
- 海东主线收费站治超：货车近景通常无定位水印，必须与前后收费站照片和记录中的驻守时间段联合判断。
- 曹家堡机场、曹家堡收费站、海东主线收费站之间时间间隔很短，不能以单张水印POI名称替代路线顺序。

### 延伸和绕行

- `01594` 不是只在K1800-K1836闭环：同仁路口驶入后完成西过境，再向东到海东主线收费站驻守治超，最后从同仁路口离开。

## 易混淆项

1. **朝阳互通和同仁路口**：多个记录把同一组入口/出口连接道路分别命名为朝阳立交、同仁路口、柴达木路或南辅路。需要保留“主点位 + 连接段别名”，不能只做字符串等值匹配。
2. **海东主线和西宁东收费站**：图片顶棚文字与正文名称存在冲突。识别模型应输出两个独立候选，并把正文模板名称作为业务层映射，而不是修改视觉真值。
3. **G6与S101共线连接段**：G0611、S1113、朝阳、韵家口、柴达木路附近照片可能属于G6、西过境或S101任一路线，必须依靠整组轨迹。
4. **定位水印POI漂移**：万方城、北山美丽园、青旅商务大厦、曹家堡服务区、机场、物资公司等是附近POI，不等同于巡查点位。
5. **收费站前后方向**：同一收费站去程和返程可在数分钟内重复出现，应按时间和相邻点位确定方向，不应去重。
6. **治超和施工照片无水印**：这些照片的事件类型可由视觉确定，但精确点位和时间要依赖同组记录；如果同日有两次驻守，不能强行分配时段。
7. **OCR时间误读**：冒号常被识别为点、横线或数字，例如 `01595/05` 的10:15被识别为10:45。原图大字时间和正文时序应共同校正。

## Benchmark 分组与命名口径

- `groupId` 对应正式现场记录编号，同一记录的全部附件使用相同 `groupId`。
- `sessionId` 对应一次连续出车巡查。同一日期并行车辆、不同线路或同线路不同时段必须使用不同 `sessionId`。
- `01592` 包含上午和下午两次G6巡查：上午为 `01592-1`，下午为 `01592-2`。`05.jpg`、`11.jpg` 缺少时间且不能判定属于哪次驻守，`sessionId` 为 `null`，不进入会话分组指标。
- `01598` 包含上午和下午两次G6巡查，分别为 `01598-1`、`01598-2`；`11.jpg` 虽无精确时间，但由前后顺序可确定属于下午会话。
- 其余记录均为单一连续会话，`sessionId` 使用 `<recordId>-1`。
- 分组准确率以日期为边界，对算法输出簇与真实 `sessionId` 做最大重叠的一对一匹配，再计算正确归组图片比例。这样会惩罚把同线路多趟合并，也会惩罚把一趟拆成多个孤立簇。
- `benchmarkPoint` 是评估用点位本体：合并同一实体的方向性别名，例如大酉山左右幅统一为“大酉山隧道”、海东收费站入口/出口统一为“海东主线收费站”；不会把曹家堡西错误合并为曹家堡东。
- `01592/02.jpg` 只能定位到曹家堡附近路段，无法形成唯一 `benchmarkPoint`，不进入点位和规范命名指标。
- `expectedNormalizedName` 不采用历史随机哈希名。命名基名取 `benchmarkPoint`，施工统一为“施工监管”，治超统一为“治超”；同一 `groupId` 内同基名多张图片按 `sequenceIndex` 和时间依次添加1、2等序号，扩展名统一为 `.jpg`。
- Benchmark 输入只包含匿名文件名和 `vision-ocr.json` 文本，不向算法提供 `expectedName`、`semanticPoint`、`benchmarkPoint`、记录编号或会话编号。
- 时间准确率只统计 `expectedTime` 非空样本，要求分钟完全一致，容许误差为0分钟。
- 默认门禁为六项指标均不低于95%。`npm run benchmark:history` 执行门禁，任一指标未达标即退出码1；`npm run benchmark:history:report` 只输出报告、不阻断。
